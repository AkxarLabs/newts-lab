# Design a room

<!-- newts:contract (generated by tools/workflow.py render-docs from workflow/) -->
**First, load this procedure's brief:** `uv run --with pyyaml python tools/workflow.py brief design-room [--study <slug>]` (skip it if a `NEWTS STAGE BRIEF /design-room` block is already in your context). It carries the PI's own instructions for this procedure. This file is the procedure's **contract**: its steps, guard calls, gates, stop points and records always bind, and win over the brief on any conflict.
<!-- /newts:contract -->

The lab's world is a tabletop of rooms. Which rooms exist, and which states and procedures each holds, is
the workflow's (the PI decides in Compose); how a room LOOKS is DATA — one JSON object: its size and colours,
furniture by name with positions, a station per procedure, and any new furniture as a list of simple shapes.
It is never code: the dashboard builds it. You write one such object from the PI's description, as a
candidate; the PI previews it in 3D and accepts or discards it in Compose. You never edit the lab's own files.

Input: `<room-id> <description>` — the first word is the room's id, the rest is what the PI wants.

1. **Read what the room must hold:** `uv run --with pyyaml python tools/workflow.py room <room-id>`. It
   prints the room's title, its states, the procedures that run in it (each needs a station), its gate if
   it has one, and where the kit and the examples are. If the room is unknown, stop and say so.
2. **Read the kit and two examples:** `dashboard/static/world3d/kit.js` (the theme colour names, and
   `defineRoomData` — exactly how your JSON is built), `dashboard/static/world3d/components.js` (the
   furniture you can use by name, and its `props`), and the two `dashboard/static/world3d/rooms/*.js`
   closest to what the PI described (the same fields, written as code). The starter looks in
   `dashboard/static/world3d/looks/*.json` are worked examples in exactly your format — a Lab per project
   type — so read the closest one too. A room id like `lab.ml` means the Lab's look for projects of that
   type: key the design `lab.ml` and make the type obvious at a glance.
3. **Write the design** to `lab/.bus/designs/<room-id>/room.json` — nothing else, nowhere else. One object:
   ```json
   {"key": "<room-id>", "title": "The …", "size": [10, 7], "floor": "tiles", "accent": "blue",
    "props": [{"c": "workstation", "at": [-2.5, -2.3], "props": {"monitors": 2}},
              {"c": "<room-id>-screenwall", "at": [1.5, -3.2]}],
    "components": {"<room-id>-screenwall": {"parts": [
        {"shape": "box", "size": [3, 1.6, 0.12], "at": [0, 0.5, 0], "color": "black"},
        {"shape": "box", "size": [2.8, 1.4, 0.02], "at": [0, 0.6, 0.07], "color": "screen", "glow": true}]}},
    "stations": {"analyze": [-2.5, -1.6, 3.1416]}, "roleStation": {"overseer": [1.5, -2.2, 3.1416]}}
   ```
   - `size` is [width, depth] in metres (about 8–12 × 6–8); `floor`, `accent` and every `color` are theme
     colour names (kit.js) or `#rrggbb`;
   - `props`: furniture by name — the kit's, or yours — at room-local `[x, z]` (x across, z toward the
     open front; the back wall is at -depth/2), `rot` in radians; keep a clear walkway from the front edge to
     every station;
   - `stations`: one `[x, z, facing]` for EVERY procedure step 1 listed, standing in front of the furniture
     where that work happens (facing π = toward the back wall); `roleStation` for subagent roles, if you like;
   - `components`: new furniture only when the kit has nothing close — each a list of `parts`, a part being
     `{shape: box|cyl|cone|sphere, size, at: [x, y, z], color, rot?: [rx, ry, rz], glow?, alpha?}` (box size
     [w, h, d] · cyl [rTop, rBottom, h] · cone [r, h] · sphere [r]; `at` y is the part's base, a sphere's
     centre); name each `<room-id>-<thing>`;
   - limits: 150 props, 40 components, 120 parts each, 1500 parts in all.
4. **Check it:** `uv run --with pyyaml python -c "import json,sys; json.load(open(sys.argv[1]))" lab/.bus/designs/<room-id>/room.json`
   must pass; fix anything it reports.
5. **Write `lab/.bus/designs/<room-id>/notes.md`:** two or three sentences on the idea, then one line per
   station (which furniture, why there), then anything from the description the kit could not do.
6. Finish with the run footer. The design now waits in Compose → Rooms → the room → **Look**, where the PI
   sees it in 3D and takes it into their draft (checked again there) — or asks you again with a sharper description.
